Especificação de Caso de Uso: Gerenciar Agenda
1.   Breve Descrição
Este caso de uso permite que o Ator organize, crie, edite e acompanhe os compromissos, audiências, prazos e reuniões da agenda jurídica.
2.   Fluxo Básico de Eventos
O caso de uso segue um padrão de visualizar, adicionar, editar e excluir os compromissos.
2.1.   Visualizar Compromissos
2.1.1.   O Ator acessa o módulo de "Agenda" através do menu principal.
2.1.2.   O frontend envia uma requisição ao backend para recuperar a listagem de compromissos ativos.
2.1.3.   O sistema consulta os registros persistentes no Banco de Dados.
2.1.4.   O sistema exibe os compromissos em uma visualização de calendário / tabela organizada.
2.1.5.   O Ator visualiza informações.
2.2.   Adicionar Compromisso
2.2.1.   O Ator clica no botão "Novo Compromisso".
2.2.2.   O sistema abre um formulário solicitando dados como: Título, Data, Horário de Início/Término, Categoria (Audiência, Reunião, Prazo, Tarefa), Local/Link, Descrição e Responsável.
2.2.3.   O Ator insere os dados do compromisso.
2.2.4.   O Ator aciona o comando "Salvar".
2.2.5.   O sistema valida e verifica a integridade dos campos obrigatórios.
2.2.6.   O sistema persiste o novo registro no banco de dados.
2.3.   Editar Compromisso
2.3.1.   O Ator seleciona um compromisso específico na lista e clica na opção "Editar".
2.3.2.   O sistema carrega as informações atuais do compromisso no formulário de edição.
2.3.3.   O Ator realiza as alterações necessárias (ex: alteração de horário, local ou categoria).
2.3.4.   O Ator confirma a atualização.
2.3.5.   O sistema valida as informações e sobrescreve o registro no banco de dados.
2.3.6.   O sistema confirma o sucesso da operação e atualiza a interface.

2.4.   Excluir Compromisso
2.4.1.   O Ator seleciona a opção "Excluir" em um compromisso da listagem.
2.4.2.   O sistema exibe um alerta de confirmação para evitar a perda acidental de dados históricos.
2.4.3.   O Ator confirma a exclusão definitiva.
2.4.4.   O sistema remove o registro e todas as notificações vinculadas do banco de dados.
2.4.5.   O sistema remove o compromisso da lista visual e atualiza.
3.   Fluxos Alternativos
3.1.   Tentativa de cadastro fracassada:
3.1.1.   No ponto 2.2.4 quando o Ator aciona o comando "Salvar". E os dados tiverem incorretos acontecerá o seguinte o fluxo.
3.1.2.   O usuário envia ao sistema os dados, no entanto, os dados enviados são inválidos.
3.2.   Tentativa de edição fracassada:
3.2.1.   O Ator realiza as alterações necessárias (ex: alteração de horário ou categoria).
3.2.2.   O usuário envia ao sistema os dados, no entanto, os dados enviados são inválidos.
3.3.   Filtrar compromissos por categoria ou período:
3.3.1.   O Ator pode aplicar filtros na visualização (por Audiência, Prazo, Reunião, etc. ou por intervalo de datas), atualizando a exibição dos compromissos na tela.
4.   Subfluxos
Não possui subfluxo
5.   Cenários Chave
Os cenários chaves deste caso de uso podem ser definidos por criar, editar, listar, filtrar e excluir compromissos da agenda.
6.   Condições Prévias
O Ator deve estar devidamente autenticado na plataforma Software Wise.
7.   Pontos de Extensão
Os dados são persistidos e armazenados de forma segura
8.   Requisitos Especiais
A princípio não foram identificados requisitos especiais.
